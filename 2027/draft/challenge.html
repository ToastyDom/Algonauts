Challenge overview

Our goal is to provide a platform where participants can develop and train brain encoding models for active gameplay, then test how well the models generalize within and across games. An encoding model uses a subject’s gameplay data to predict the corresponding fMRI time series.

We provide gameplay video, audio, controller actions and annotated game events from four retro video games, together with the corresponding fMRI responses of six subjects. Challenge participants build encoding models that predict brain responses for held-out gameplay from these games (in-distribution, ID) and for previously unseen games (out-of-distribution, OOD), for which the brain data are withheld. Submissions are scored on Codabench.

Development Phase. Participants train their encoding models on gameplay data and corresponding fMRI responses from all four games. For in-distribution testing, we reserve selected runs from Super Mario All-Stars and Super Mario Bros. 3 (see the in-distribution test split). We release all model input modalities for these test runs and keep the corresponding fMRI responses hidden. Participants submit predicted fMRI responses to Codabench and can compare model variants using their prediction accuracy scores on a public leaderboard.

Generalization Phase. At the beginning of this phase, we release about two hours of gameplay per subject from games that are not part of the model training data, and withhold the corresponding fMRI responses. We reveal the identities of these games when the Generalization Phase begins. They were selected to differ from the Mario-family games in visual appearance, behavioral demands and cognitive demands. Performance in this phase determines the final ranking.

Post-Challenge Benchmark. Once the challenge is over, both leaderboards remain open indefinitely as public benchmarks for ID and OOD generalization.

Evaluation

For each subject and game, the scoring program concatenates the predicted and withheld fMRI responses across evaluated gameplay recordings. Longer recordings contribute more time points. It then computes Pearson’s correlation coefficient (r) between the two time series for each of the 1,134 brain parcels. We average the parcel correlations to obtain one score per subject and game. We then average game scores within each subject, weighting games equally. Finally, we average the subject scores to obtain a single prediction accuracy score per submission. We apply this procedure to both the ID and OOD test sets.

Five subjects are evaluated: sub-01, sub-02, sub-03, sub-05 and sub-06. Subject sub-04 played only Shinobi III. Data from this subject are provided for training only.

Prepare a submission

Participants submit predicted fMRI responses to Codabench: for the ID test runs during the Development Phase, and for the unseen games during the Generalization Phase. The Challenge submission section of the Development Kit explains what to upload, including the required files, the prediction format and the ordering of the predictions (to be finalized).

Validate before submitting (optional)

To check cross-game generalization before the Generalization Phase, you can train on the Mario recordings and reserve Shinobi III for validation. This tests transfer beyond the three related Mario games to a game with different sensory content, actions and game events. This split is available for sub-01, sub-02 and sub-06, who have recordings from both the Mario games and Shinobi III.

This validation is something you run yourself on the released model training data. It is separate from the official ID and OOD test sets, whose fMRI responses stay hidden and which are scored only on Codabench.

Challenge rules

  1. Challenge participants can use any encoding model, pretrained representation or external training data. Using the withheld fMRI responses of the test data is prohibited.
  2. The winners are determined by performance in predicting fMRI responses for the unseen games during the Generalization Phase.
  3. We allow unlimited submissions per team during both competitive phases. Each team may participate using only one account. Using hidden test fMRI responses or participating with multiple accounts results in disqualification.
  4. To be considered for the final ranking, teams must publish a short report (approximately 4–8 pages) describing their encoding model and methodology on a preprint server. The top three teams must make their code publicly available and are invited to present their approach at CCN 2027 in Edinburgh.

Development Kit

The Development Kit is an interactive Python notebook that runs on Google Colab or locally in Jupyter. It introduces the challenge data, walks through the baseline encoding model, and explains how to prepare a submission.

  1. Setup: install the required libraries and access the tutorial data.
  2. Data familiarization: explore gameplay recordings, controller actions, game events and fMRI responses.
  3. Feature extraction: extract visual, audio, controller-action and game-event features.
  4. Encoding model training: train and test an fMRI encoding model using the supplied features.
  5. Challenge submission: prepare and format predicted fMRI responses for submission to Codabench.

Baseline model

We provide a challenge baseline model as a working example and a reference point for prediction accuracy. Participants may use their own features, model architectures, and training strategies. Features from four stimulus modalities are aligned to the 1.49-second fMRI sampling grid, combined across a window of recent gameplay shifted for the hemodynamic delay, and mapped onto each of the 1,134 parcels with ridge regression. Encoding models for fMRI prediction

Participants may choose their modeling approach within the challenge rules. One common approach is a linearizing encoding model. It predicts the fMRI response of each brain parcel independently from features extracted by a computational model, typically using linear regression (Wu et al., 2006; Naselaris et al., 2011; Kriegeskorte & Douglas, 2019). The Development Kit implements such a model.
