Challenge overview

The goal of the Algonauts Project 2027 challenge is to provide a platform where participants can train encoding models of human fMRI responses during gameplay, and then test these models’ generalization both in-distribution (ID) and out-of-distribution (OOD).

We provide gameplay video, audio, controller actions and annotated game events from four retro video games, recorded while six subjects played them during fMRI. Challenge participants train encoding models on three of these games and predict brain responses for the fourth, the Super Mario Bros. remake from the Super Mario All-Stars collection (in-distribution, ID), and for hidden games (out-of-distribution, OOD). The brain data of both test sets are withheld. Submissions are scored on Codabench.

Development Phase. We release gameplay data and the corresponding fMRI responses for all levels of the three model training games. For the in-distribution test game, Super Mario All-Stars, we release the gameplay data and keep the fMRI responses hidden. Participants submit predicted fMRI responses for it to Codabench (see Prepare a submission) and compare model variants on a public leaderboard.

Generalization Phase. We withhold the OOD game identities until this phase begins to limit game-specific preparation. We provide approximately two hours of gameplay data per subject, with the same gameplay data modalities as during the Development Phase, and keep the corresponding fMRI responses hidden. Participants submit predicted fMRI responses to Codabench for automatic scoring and leaderboard updates. This leaderboard determines the final challenge ranking.

Post-Challenge Benchmark. Both leaderboards remain open as public benchmarks, so participants can keep submitting predictions for the ID and OOD test sets.

Evaluation and submission

For each subject and game, Codabench concatenates the predicted and measured fMRI time series across all corresponding gameplay videos in the test set. It then calculates Pearson’s correlation coefficient (r) between the predicted and measured sequences separately for each of the 1,134 brain parcels. The platform averages the parcel correlations to obtain one score per subject and game. For the OOD test set, which contains multiple games, it averages game scores within each subject, weighting games equally. It then averages the scores across subjects to obtain a single prediction accuracy score per submission for each test set. Codabench uses the ID scores to rank submissions on the public leaderboard during the Development Phase, and the OOD scores to determine the final challenge ranking.

Five subjects are tested: sub-01, sub-02, sub-03, sub-05 and sub-06. Subject sub-04 played only Shinobi III. Data from this subject are provided for training only.

Prepare a submission

Participants submit predicted fMRI responses to Codabench: for Super Mario All-Stars during the Development Phase, and for the OOD games during the Generalization Phase. The Challenge submission section of the Development Kit explains what to upload, including the required files, the prediction format and the ordering of the predictions (to be finalized).

Validate before submitting (optional)

Before submitting predictions, you can divide the released model training data into training and validation partitions. Fit the model using only the training partition, then compare its predictions with the recorded fMRI responses in the validation partition to assess model choices.

To check cross-game generalization before the Generalization Phase, you can train on Super Mario Bros. and Super Mario Bros. 3 and reserve Shinobi III for validation. This tests transfer beyond the related Mario games to a game with different sensory content, actions and game events. This split is available for sub-01, sub-02 and sub-06, who have recordings from both the Mario games and Shinobi III.

This validation is something you run yourself on the released model training data. It is separate from the official ID and OOD test sets, whose fMRI responses stay hidden and which are scored only on Codabench.

Challenge rules

  1. Challenge participants may use any encoding model, pretrained representation, or external training data. Training models on any neural responses for the ID or OOD test gameplay data is prohibited.
  2. We allow unlimited submissions per team during the Development Phase and up to ten submissions per team during the Generalization Phase. Each team may participate using only one account.
  3. Training on neural responses for the test gameplay data, exceeding the submission limit, or participating using multiple accounts will result in disqualification.
  4. To be considered for the final ranking, teams must publish a report of approximately 4–8 pages describing their encoding model and methodology on a preprint server by the report deadline.
  5. The top three teams must additionally make their code publicly available by the code deadline. They will receive monetary prizes and be invited to present their methods at CCN 2027 in Edinburgh.

Development Kit

The Development Kit is an interactive Python notebook that runs on Google Colab or locally in Jupyter. It introduces the challenge data, walks through the baseline encoding model, and explains how to prepare a submission.

  1. Setup: install the required libraries and access the tutorial data.
  2. Data familiarization: explore gameplay recordings, controller actions, game events and fMRI responses.
  3. Feature extraction: extract visual, audio, controller-action and game-event features.
  4. Encoding model training: train and test an fMRI encoding model using the supplied features.
  5. Challenge submission: prepare and format predicted fMRI responses for submission to Codabench.

Baseline model

We provide a challenge baseline model as a working example and a reference point for prediction accuracy. Participants may use their own features, model architectures, and training strategies. Features extracted from the gameplay data are aligned to the 1.49-second fMRI sampling grid, combined across a window of recent gameplay shifted for the hemodynamic delay, and mapped onto each of the 1,134 parcels with ridge regression. ID prediction score on Super Mario All-Stars: r = 0.209.

Encoding models for fMRI prediction

Participants may choose their modeling approach within the challenge rules. One common approach is a linearizing encoding model. It predicts the fMRI response of each brain parcel independently from features extracted by a computational model, typically using linear regression (Wu et al., 2006; Naselaris et al., 2011; Kriegeskorte & Douglas, 2019). Gameplay features describe the sensory input, controller actions, and game events used to predict brain responses. Using paired gameplay features and fMRI responses from the training data, ridge regression learns a weighted combination of features for each brain parcel. The trained mapping is then applied to features from the test gameplay data to predict the corresponding fMRI responses. The Development Kit implements this approach.
